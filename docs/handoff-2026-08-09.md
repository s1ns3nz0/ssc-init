## 1. What this project is

`ssc-init` is a standalone, CGO-free, Darwin-only Go binary for developer
supply-chain inventory. It discovers agent plugins/skills, IDE extensions, MCP
declarations, packages and project manifests, hashes bounded content evidence,
and persists atomic SQLite snapshots. All commands emit JSON.

**It is not a scanner and makes no safety claims.** This build performs no
content analysis and has no threat intelligence, so it produces no malware
verdicts and blocks nothing. Those *are* in the approved design (§7.3, §9.1,
§9.4) but unbuilt. When you write user-facing copy, state that limitation as
*current capability*, never as a permanent principle — that distinction was
corrected once already and the wording is load-bearing.

**Authority documents**, in precedence order:

| Document | Role |
|---|---|
| `docs/superpowers/specs/2026-08-05-ssc-init-design.md` | The foundation design, §1–§12. The final authority. |
| `docs/superpowers/specs/2026-08-0{6,7,8}-*.md` | Later approved designs that narrow or supersede parts of it. |
| `docs/superpowers/plans/*.md` | Per-program implementation plans. |
| `CLAUDE.md` | Repo conventions, architecture map, release-blocking invariants. |

`CLAUDE.md` is named for the tool that wrote it but is tool-agnostic content —

### Decisions the user already made — do not relitigate

- **Bootstrap: the adapter hands over the file; the core never downloads.**
  This preserves the product's zero-network property. `ssc-init install --from
  <path>` verifies digest and signature on a file it is given.
- **Notarization ships a stapled `.dmg`/`.pkg`,** not a bare binary. `xcrun
  stapler` cannot staple a bare Mach-O, and §2 requires offline usability.
- **Severity ladder semantics** (see `docs/superpowers/specs/2026-08-08-hook-severity-ladder-design.md`)

## 4. How work is done here

Every program follows the same loop, and it has repeatedly caught real defects.
You do not need any particular tooling to follow it.

1. **Plan before code.** Each program has a plan document with numbered tasks;
   each task has explicit files, a failing test, the expected failure text, the
   implementation, and a commit message.
2. **Strict TDD.** Write the test, *run it and watch it fail with the expected
   message*, then implement. A test nobody has watched fail is not evidence.
3. **Independent review per task.** A reviewer that did not write the code
   verifies by execution and mutation — not by reading.
4. **Fix rounds start with a reproducing failing test**, never with a patch.

### Gates — run all of these before considering anything done

```sh
go build ./...
go vet ./...
go test -race -count=1 ./...
go mod verify
git diff --check
go test ./scripts -count=1        # requires a CLEAN tracked worktree
```

`go test ./scripts` runs the release build and refuses to run against a dirty
or untracked-file-bearing worktree. Commit first, then run it.

### Commit convention

Conventional Commits (`feat:`, `fix:`, `test:`, `docs:`, `ci:`, `refactor:`).
Commits in this repo carry a `Claude-Session:` trailer — **that is specific to
the previous agent; do not add it.** Use whatever attribution your own tooling
prescribes, or none.

## 5. Release-blocking invariants

From `CLAUDE.md`. Breaking one of these is not a bug, it is a release blocker.

- Evidence filesystem access is **descriptor-rooted and never follows
  symlinks**; a target cannot escape its verified collector root, and no
  absolute path is reconstructed after root verification.
- Target catalogs are exact and closed; every accepted evidence target receives
  **exactly one terminal result**; only `complete` evidence is a trusted digest.
- **Never persist** raw content, secrets, absolute paths, tree leaf names,
  link targets, fingerprints, anchors, or runtime provenance.
- Default scans **execute no process and perform no network access**;
  discovered content is never executed. (`install`/`rollback` deliberately do
  execute the staged core for its health check — that is documented as *not a
  scan*, and the justification lives in a doc comment on `coreHealthCheck`.)
- Cancellation and deadline errors propagate **and clear partial runtime
  state**; hostile targets are isolated from safe siblings.
- **No new runtime dependency** without revising the plan first. Deterministic
  input produces byte-identical report JSON and snapshot state.
- Validation errors are **fixed and value-free** — they never echo the
  offending path, digest, version, or content.

## 6. Gotchas that have already cost time

**`git archive` exports are booby-trapped.** Running `go test ./...` inside a
`git archive` export makes `scripts/build-darwin_test.go` check a *newer* tree
out over the working directory — adding `.git/` and `dist/` and overwriting
tracked files — so the export silently stops representing the commit you
pinned. Three separate agents hit this. **Verify pinned commits in a real `git
clone`, or exclude `./scripts`.**

**`os.Root` follows symlinks that stay inside the root.** A planted
`current.tmp → versions/v0.1.0/ssc-init` turned a pointer write into a write
primitive against an installed core. Assume rooted access prevents *escape*,
not *redirection within the root*.

**`?mode=ro` on SQLite creates `-wal` and `-shm`.** A function measuring the
store was creating a 32 KiB file as a side effect of reading, making its own
measurement wrong. `immutable=1` avoids it but fails against an open store,
because the schema lives in the uncheckpointed WAL. The current code branches
on whether a non-empty `-wal` exists.

**`VACUUM` in WAL mode writes *through* the log.** Footprint measured 48.87 MB
db + 49.16 MB WAL immediately after vacuuming — worse than before, until
`wal_checkpoint(TRUNCATE)`. Measure `db + -wal`, never `db` alone.

**Go's non-multiline `$` matches before a trailing newline.** `^v[0-9.]+$`
accepts `"v1.0.0\n"`. Use `\A…\z` when validating anything that becomes a
filename.

**Concurrent writers in one worktree collide.** Two agents editing the same
package caused `git add <paths>` to sweep another's unstaged work into the
wrong commit. Serialize writers per package, or use separate worktrees.

## 7. The failure mode to watch for

Across every program, the most common defect was **an assertion that asserts
nothing**. Concrete instances, all found by deliberately breaking the code:

- Setting the 30-day retention window to **zero** — delete every snapshot but
  the newest, on every save — passed four packages.
- A performance test asserting "warm cache is faster than cold" passed with the
  cache **completely dead**, because the OS page cache carried the second run.
- Four of twelve child tables in an orphan check had fixtures that wrote **no
  rows**, so dropping them from the prune list passed everything.
- Three test fixtures used asset IDs **no collector can mint**, so the
  assertions standing on them passed by coincidence.
- A cancellation path never cleared sealed runtime state — a release-blocking
  invariant, violated, with no test watching.

**Mutate the code and confirm something screams.** If nothing fails, the test
is decoration. This is the single highest-value habit in this repository.
